五条铁律

每一条都从使用场景推导，不是口味偏好。

01

光，不是边框。层次来自顶光与投影。删掉任何一处 1px 灰边，画面都不应该塌。

02

一个主角。比分是全站唯一的巨型元素。标签一律 ≤11px 且加宽字距，永远不与数字争。

03

两条线定义一场球。中线是网、外沿是边线。队色只出现在线、数字、光池里，不做装饰。

04

一场比赛有一条形状。得分流水升级为回合时间轴，一屏读出势头与转折。

05

动效只服务得分。其余交互 ≤120ms 或不做。得分时数字「砸」进来，并有一道光扫过本方半场。

与旧版逐条对账

为什么旧版「丑」
问题旧版（v3 方向 C）v4 夜场
面板是平的 --sh-flat: none，全靠 1px 灰边分层。暗色下边线不可见，整屏塌成一块死灰。 两段渐变 + 顶部内高光（--lift）。光从上面来，深度自然出现。
圆角「没决定」 全站铺 2 / 3 / 4 / 6 / 10px 五档圆角，既不像矩形也不像圆角。 只留两种决定：面板一律锐角（边线语言），交互一律全圆。
数字不够大 比分 clamp(52–76px)，在 390px 机上只有 66px。 clamp(84px, 36cqi, 140px)，390px 机上 140px（占半屏 78%）。场边模式 205px。
没有主角 26px 标题、13px 正文、76px 比分三层挤在一起，读起来「什么都没强调」。 一档巨型 + 三档小字（15 / 13.5 / 11 / 9.5）。中号层整层删除。
刻度环是装饰 比分外 40 格 conic-gradient 刻度环。好看，但不承载任何信息。 换成进度线：刻度落在 11 分（间歇）与目标分上，同时给出「离局点还有几分」。
得分流水读不出势头 一串文字行「林知远 10 → 11」，要一行行读才知道谁在连得。 回合时间轴：每分一根竖条，按队伍着色。连得、追平、转折一瞥即得。
队色占了太多面积 3px 顶条 + 头像 + 队标 + 比分 + 局分 + 发球点，六处用色。 收敛到三处：外沿边线、比分、进度线。其余全部中性。
落后方处理反了 落后方降不透明度（opacity:.62）——在暗色下直接变成看不清。 落后方用固定 62% 象牙白（对比度达标），领先方才升到队色 + 光晕。
顶栏只有标题 左侧「记分」两个大字，右侧三个图标，中间空。 标题 + 赛制摘要（21 分 · 三局两胜）+ 图标。顶栏终于有信息。
动效廉价 得分数字 scale(1.09) 回弹——所有 UI 框架的默认动效。 得分时数字「砸」进来（白闪 + 从 1.07 落到 1），同时一道光扫过本方半场。
配色是「石墨」 #101113 中性石墨，球馆冷光下发蓝发脏。 #0A0D0C 夜场墨绿黑，在冷光下仍然干净。

实现时对设计稿的修正

下面每一条都是照着稿子做完、在真实页面上看出来的问题。设计稿不是最终答案。

01

得分动效换掉了。稿子写「一道光扫过本方半场」，但代码里留的还是 v3 那个 40px 实心扩散圆——它是一块半透明色块压在数字上，不是光。改成铺满半场的渐变光带，用 background-position 扫过：用 transform 位移整个元素会让光带从边缘「切」进来，留下一道硬边。

02

时间轴的换边线原本指错了位置。稿子只画了效果，没写坐标怎么算。第一版拿 switchAt / target（比分轴）当轨道百分比，而轨道横轴是回合序号——21 分制下这条线落在第 13 回合，标签却写着 11。改成累计比分找第一次越过换边分的那一回合。

03

高光徽章和 Toast 原本叠在一起。两者各自 position: fixed 在同一个 top，而「换边提醒」和「赛点！」是同一分触发的——两块面板直接互相盖住。合并进一条 .notice-rail 竖列。

04

Toast 的左边那道琥珀被换掉了。稿子规定「琥珀只有一个含义：进行中」，但 toast 承载的是「已保存 / 请输入金额」这类通用消息。拿「进行中」的颜色去标一条「保存成功」，等于把这个颜色作废。改成 --fg-3。

05

排行榜的名字和数据粘在一行。.rname / .rsub 在 DOM 里是 <span>，默认 inline，读出来是「李大力5 场 · 胜率 40%」。显式改成块级。

06

比分进度线的刻度是 11 点，不是 11%——稿子的示意图按百分比画，实现按真实换边分算（21 分制 11 / 15 分制 8 / 11 分制 6）。

07

显示字体从 DIN 换成了自带的 Barlow Semi Condensed。稿子写的是「数字用等宽体」，但没有指定字体族，实现沿用了 DIN Next LT Pro → Bahnschrift 的系统栈——这两个只有 Windows 有，iOS / Android 会一路回落到 PingFang SC（中文正文字体），而手机才是球馆现场的主形态。改成随包分发（OFL，3 档 68KB，unicode-range 锁拉丁区，中文仍走系统）。选型依据是实测：140px 下 Barlow 数字宽 74.9px，比 DIN 的 77.8px 更窄，半场只有 194px 宽，窄的字形能换来更大的比分；Archivo 同字号 87.8px，宽 13%，是反向的。

06

落地说明

怎么把这套设计接进现有工程

替换范围

只改视觉层，不动任何业务代码。

改

css/tokens.css、base.css、components.css、screens.css、courtside.css、share-card.css、effects.css。

不动

js/ 全部业务模块、server/、test/、tools/。
localStorage 的 10 个键名与字段结构逐字不变。

新增

只有时间轴需要新 DOM：把 #point-log 的渲染结果同时映射成一组 .tl-bar。
数据源不变（还是那份得分流水），只是多一个视图。

同步

改 tokens.css 后必须同步 js/tokens.js 的 palette() 回落字面量、share-card.css、以及 sw.js 的 CACHE_NAME。

字体授权（上线前必须决定）

本设计稿用的 DIN Next LT Pro 是商业字体，随项目分发即侵权。二选一。

A

购买 DIN Next LT Pro 授权并自托管 woff2。
字形最好，但按年计费、按域名算。

B

换成 OFL 开源体：Archivo（几何、tabular 数字，最接近）或 Barlow（略窄，更「器械」）。
零成本、可自托管、可商用。已写入字体栈回落位。

—

中文用 Noto Sans SC（SIL OFL），可放心自托管。当前已回落系统黑体。

待实测项

设计稿已渲染校验，但以下是本设计稿无法覆盖的，需在真实设备上验收。

1

真机 2 米可读性（场边模式 205px 是计算值，不是肉眼结论）。

2

得分动效在低端安卓上的帧率（filter: brightness 触发重绘）。
若掉帧，降级为纯 transform 缩放。

3

html2canvas 对 color-mix() / 渐变文字的支持——分享卡仍按旧约定只写字面量。

4

iOS 安全区与横屏刘海（场边模式）。

5

长按撤回的 520ms 阈值在新视觉下是否仍有足够反馈（v4 未改交互）。
