# 羽毛球极速计分板 · Figma 设计系统插件

把「夜场 NIGHT COURT」这套视觉语言**一次性写进 Figma**，生成一份可编辑、
可继续打磨的设计源文件 —— 变量、样式、组件、12 个界面、场边与分享卡，全都有。

## 为什么是插件，不是 Figma MCP

Figma 的 MCP 读写工具受**计划额度**限制：Starter 计划 + View 席位 = 每月 20 次调用。
建一套完整设计系统需要几百次调用，额度瞬间见底。

本地插件走的是**同一套 Figma Plugin API**，但不受额度限制，而且可以反复重跑 ——
改一行 `code.js` 再跑一次，文件就会按新版本重建，不用手工收拾。

## 怎么用

1. 打开 Figma 桌面版或网页版，随便新建一个文件（或打开你已有的文件）。
2. 顶部菜单 **Plugins（插件）→ Development（开发）→ Import plugin from manifest…**
3. 选中本目录的 `manifest.json`（`figma-plugin/manifest.json`）。
4. 再进 **Plugins → Development**，点 **羽毛球计分板 · v4 夜场 NIGHT COURT**。
5. 插件会弹出一个深色进度窗，约 10–30 秒跑完，结束后 5 个页面就已生成。

想再跑一遍（比如改了色值）：直接重跑即可。插件会先清空它自己上次生成的 5 个页面，
再重新建 —— **不会**碰你在这个文件里自己画的任何东西。

## 会生成什么

| 页面 | 内容 |
| --- | --- |
| **封面 Cover** | 方向说明、五条铁律、色板速览 |
| **基础 Foundations** | 全部设计令牌：色板、字阶、间距、圆角、光影演示 |
| **组件 Components** | 按钮（6 态）、芯片、标签、选择卡、输入框、开关、列表项、数据卡、分段控件、回合时间轴 |
| **界面 Screens** | 12 个真实界面 @390×844：记分 / 智能分组 / 费用分摊 / 比赛历史 / 排行榜 / 能力分析 / 成就 / 我的 / 比赛设置 / 绑定头像 / 数据备份 / 关于 |
| **场边与分享** | 场边横屏 844×390、场边竖屏 390×844、分享卡 360×420 |

同时会建好 **71 个变量**（分 3 个集合）、**18 个样式**（6 个效果 + 12 个文字），
并且所有颜色和尺寸都已**真实绑定到变量** —— 改一个令牌，整份稿子跟着变。

### 变量集合

| 集合 | 内容 |
| --- | --- |
| `1 · 基色 Primitives` | 18 个原始色值。作用域留空，在属性面板里隐藏 —— 基色是原料，不该被直接使用 |
| `2 · 语义 Semantic` | 20 个语义色，全部**别名**到基色。属性面板里能用的是这一层 |
| `3 · 尺度 Scale` | 33 个数值令牌：间距 / 圆角 / 字号 / 布局 / 动效时长 |

每个变量都带 Web 代码语法（`var(--void)` 这种），开发者模式可直接复制。

## 字体

读数族用 **Barlow Semi Condensed**（SIL OFL 授权，站内已自带 woff2）。
它比 DIN Next LT Pro 更窄，同样的宽度能撑出更大的比分数字 —— 这是选它的唯一原因。

**插件不会联网下载字体。** Figma 用的是你账号字体库里已有的字体：

- **想看到设计原貌**：先在 Figma 里装上 Barlow Semi Condensed 和 Noto Sans SC
  （Google Fonts 免费，Figma 桌面版装到系统后重启即可）。
- **懒得装**：插件会自动回落 —— 读数族退到 Inter，中文退到 Microsoft YaHei，
  版式结构完全一致，只是数字不够窄、不够冲。运行结束的进度窗里会明确告诉你回落到了哪个字体。

## 设计约束（改稿前先读）

这套设计有五条铁律，改任何东西之前先确认没破它们：

1. **光不是边框** —— 面靠两层渐变 + 顶部内高光（`--lift`）立起来，不是「平底 + 1px 描边」。
2. **一个主角** —— 比分是唯一被放大的元素，其余标签不超过 11px。
3. **两条线定义一场球** —— 中线是球网，左右外边线是场地边线。
4. **一场比赛有一条形状** —— 得分流向画成圆形时间轴。
5. **动效只服务得分** —— 90 / 120 / 220 / 320ms 四档，不做无意义微动效。

另外两条容易踩的：

- 琥珀色 `--live` **只有一个含义：进行中**。绝不用来表示「已选中」；选中态用象牙白。
- 亮色是默认主题，暗色需要单独评审，不能靠反相糊弄。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `manifest.json` | 插件清单。`documentAccess: "dynamic-page"` + 零网络访问 |
| `code.js` | 全部生成逻辑，约 2600 行 |
| `ui.html` | 进度窗界面（深色，和主视觉同源） |
| `_smoke.js` | **开发用**无头冒烟测试，不随插件发布 |

## 改完代码怎么验

`_smoke.js` 用一个最小的 Figma API 替身把 `code.js` 完整跑两遍（模拟「改一行再跑一次」），
能抓出只有真开 Figma 才会暴露的那类错误：字体没加载就写文本、在非弹性容器子节点上设 FILL、
颜色通道越界、以及**重跑时误删用户自己的页面**。

```bash
node figma-plugin/_smoke.js
```

另外两种环境也建议顺手跑一下：

```bash
# 同步样式 API 兜底分支（老版 manifest 模式）
$env:SMOKE_SYNC_STYLES='1'; node figma-plugin/_smoke.js; Remove-Item Env:\SMOKE_SYNC_STYLES

# 字体回落路径：模拟本机没有 Barlow / Noto Sans SC
$env:SMOKE_NO_BARLOW='1'; node figma-plugin/_smoke.js; Remove-Item Env:\SMOKE_NO_BARLOW
```

三条都应该是 `PASS 无问题`。

## 真值来源

插件里的色值与尺寸**必须**和站内 CSS 同源。真值在这几处：

- `css/tokens.css` —— 全部设计令牌
- `css/screens.css` / `css/components.css` / `css/courtside.css` —— 版式与组件
- `index.html` —— 真实界面结构

改了 CSS 就要同步改 `code.js` 顶部的 `C` / `PRIMITIVES` / `SEMANTIC` / `SCALE`，
否则设计稿和线上会慢慢漂开。

## 这个目录不会被部署

`deploy-cloudflare.ps1` 用的是白名单（`css` / `js` / `vendor` / `images` / `fonts` 五个目录，
外加 `index.html` / `manifest.json` / `sw.js` / `_headers` / `robots.txt` 五个文件）。
`figma-plugin/` 不在其中，所以它只存在于你的本地仓库，不会进线上站点。
